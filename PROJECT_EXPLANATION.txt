1. PROJECT OVERVIEW & ARCHITECTURE
========================================================================================
VaxTrack is a strictly software-only CSE college engineering system designed to solve
the critical real-world problem of vaccine wastage, cold-chain temperature spoilage,
and stock imbalances between healthcare facilities and pharmaceutical manufacturers.

SYSTEM ARCHITECTURE TIERS:
--------------------------
1. Presentation Tier (Frontend):
   - Built with React 19, Vite 8, and Tailwind CSS.
   - Dual-Portal Architecture with strict role-based access isolation:
     * Portal 1: Hospital / Pharmacy Clinical Hub
     * Portal 2: National Vaccine Manufacturer & Logistics Control
   - Data visualizers powered by Recharts (multi-line thermal trends, demand curves).

2. Gateway & Proxy Tier:
   - Vite reverse-proxy forwarding `/api/*` requests to the Flask server (`http://127.0.0.1:5000`).
   - Built-in `autoBackendPlugin()`: Automatically checks if the Python backend is running
     and boots it automatically, ensuring zero-configuration startup.
   - Transparent client-side retry (`requestWithRetry`) that handles temporary latency.

3. Application / Algorithmic Tier (Backend):
   - Python 3.11 with Flask REST API.
   - Threaded single-process architecture for absolute stability on Windows.
   - Four dedicated algorithmic engines:
     * `thermal_analyzer.py`: Thermodynamic kinetics & WHO MKT calculations.
     * `demand_forecaster.py`: Time-series regression & 7/30/90-day demand predictions.
     * `redistribution_engine.py`: Supply-shortage optimization matching.
     * `simulator_service.py`: Refrigerator thermodynamic physics engine (Method A).

4. Persistence Tier:
   - SQLite relational database (`backend/vaccine_system.db`) with foreign key constraints.
   - Real-world 500-record IoT cold-chain CSV dataset (`cold_chain_dataset.csv`).

3. DATASET DETAILS & COLD-CHAIN LIFECYCLE (batch001)
========================================================================================
The project incorporates a real-world 500-row telemetry dataset tracking batch001 at the
Jharkhand Cold Storage Facility.

Data Columns:
- `timestamp`: Chronological tracking time.
- `batch_id`: "batch001"
- `current_hop`: Storage node location.
- `ambient_humidity`: Humidity percentage (45% - 75%).
- `room_temperature`: Ambient facility room temperature (20°C - 24°C).
- `shipper_temperature`: Core inside temperature of vaccine insulated shipper (°C).
- `item_expiry_hours`: Remaining shelf-life in hours.
- `out_of_bound_hours`: Duration outside safe temperature range.

THE 3-PHASE LIFECYCLE IN THE DATASET:
-------------------------------------
Phase 1: Ultra-Low Temperature (ULT) Storage (Records 1 to 380)
- Temperature maintained between -70°C and -65°C.
- Total duration: 720 hours (standard maximum capacity for dry-ice passive shippers).
- Status: HEALTHY / OPTIMAL.

Phase 2: Thawed Refrigerated Storage (Records 381 to 499)
- Transferred to standard cold storage at 2°C to 4°C.
- Shelf-life countdown begins from 120 hours down to 0 hours.
- Status: REFRIGERATED / TRANSIT.

Phase 3: Thermal Breach & Auto-Discard (Record 500)
- Severe excursion spike to +14.0°C; expiry hours drops to -1.
- Immediate tripwire triggered: Automatically moved to `dest_discarded_vaccine_storage_unit`.
- Final Status: DISCARDED / QUARANTINED.

4. ALGORITHMS & MATHEMATICAL MODELS USED
========================================================================================

----------------------------------------------------------------------------------------
A. WHO MEAN KINETIC TEMPERATURE (MKT) - ARRHENIUS EQUATION
----------------------------------------------------------------------------------------
MKT is defined by the World Health Organization (WHO) and United States Pharmacopeia (USP)
as a single derived temperature that, if maintained over the same duration, would have the
same thermal degradation impact on a biological product as the actual fluctuating temperatures.

Formula:
                      (Delta_H / R)
Tk = ------------------------------------------------ - 273.15
      -ln [ (1 / n) * SUM( exp( -Delta_H / (R * Ti) ) ) ]

Where:
- Tk       = Mean Kinetic Temperature in Celsius (°C).
- Delta_H  = Activation energy for vaccine degradation = 83.144 kJ/mol.
- R        = Universal gas constant = 8.3144 * 10^-3 kJ / (mol * K).
- Delta_H / R = ~10,000 Kelvin (standard biological Arrhenius ratio).
- n        = Total number of temperature samples recorded.
- Ti       = Each individual recorded temperature in Kelvin (Ti = Temp_Celsius + 273.15).

Code Reference: `backend/app/services/thermal_analyzer.py` -> `calculate_mean_kinetic_temperature()`

----------------------------------------------------------------------------------------
B. COLD CHAIN HEALTH DEGRADATION INDEX (0% - 100%)
----------------------------------------------------------------------------------------
Calculates real-time biological viability:
- Base Score: 100.0%
- Heat Penalty: 0.8 points deducted per minute spent above 8.0°C.
  * Accelerated penalty: +3.0 points for readings > 15.0°C; +1.0 for > 10.0°C.
- Freeze Penalty: 1.5 points deducted per minute below 2.0°C.
  * Severe sub-zero penalty: +10.0 points per reading < 0.0°C (freezing causes immediate
    aluminum adjuvant agglomeration in Hepatitis B, Tetanus, and DTP).
- Health Classification:
  * 90% - 100%: SAFE (Green)
  * 70% - 89% : WARNING (Amber)
  * < 70%     : CRITICAL_QUARANTINE (Red - Auto-locks batch from dispensing)

----------------------------------------------------------------------------------------
C. AI DEMAND FORECASTING (OLS LINEAR REGRESSION + DAY-OF-WEEK SEASONALITY)
----------------------------------------------------------------------------------------
Predicts future vaccine needs for 7-day, 30-day, and 90-day operational planning.

Step 1: Trendline Fitting using Ordinary Least Squares (OLS):
        y = m * x + c
Where:
- x = chronological time index of recorded historical administrations.
- y = daily doses administered.
- m (slope) and c (intercept) computed using numpy polynomial regression.

Step 2: Day-of-Week (DoW) Seasonality Multipliers:
Clinical clinics exhibit distinct weekly operational cycles:
- Monday    (DoW 0): 1.10x (Catch-up immunization sessions)
- Tuesday   (DoW 1): 1.25x (Peak pediatric immunization clinic day)
- Wednesday (DoW 2): 1.20x (General vaccination drive)
- Thursday  (DoW 3): 1.05x (Standard clinics)
- Friday    (DoW 4): 1.00x (Standard clinics)
- Saturday  (DoW 5): 0.65x (Half-day morning clinic)
- Sunday    (DoW 6): 0.30x (Emergency cases only)

Step 3: Confidence Intervals:
Upper and lower safety bounds: Projected Doses ± 1.2 * Standard_Deviation.

Code Reference: `backend/app/services/demand_forecaster.py` -> `forecast_vaccine_demand()`

----------------------------------------------------------------------------------------
D. FIRST-EXPIRED, FIRST-OUT (FEFO) INVENTORY ALLOCATION
----------------------------------------------------------------------------------------
Unlike FIFO (First-In First-Out) used in general warehouses, pharmaceutical supply chains
require FEFO:
- When a clinic dispenses doses or recommends redistribution, batches are sorted by:
  `ORDER BY expiry_date ASC, current_doses DESC`
- Batches with fewer days until expiration are always consumed first, minimizing spoilage.

----------------------------------------------------------------------------------------
E. REGIONAL REDISTRIBUTION OPTIMIZATION ALGORITHM
----------------------------------------------------------------------------------------
Scans all healthcare centers in the network and detects supply-demand mismatches:
1. Identifies Surplus Nodes: Facilities with Days of Supply > 50 days OR batches expiring
   in < 60 days that cannot be consumed locally before expiration.
2. Identifies Shortage Nodes: Facilities with Days of Supply < 20 days.
3. Matching Engine: Transfers up to 250 doses from the surplus node to the deficit node,
   generating automated transfer manifests and preventing vaccine loss.

Code Reference: `backend/app/services/redistribution_engine.py`

8. TOP 15 VIVA VOCE QUESTIONS & DEFENSIVE ANSWERS
========================================================================================

Q1: Why is this project strictly software-only?
A: Physical IoT hardware (such as ESP32 sensors or peltier coolers) introduces physical
   reliability issues during laboratory demonstrations. By modeling thermodynamics and
   incorporating a real-world 500-row telemetry dataset, our CSE software focuses on
   complex algorithmic logic: WHO Arrhenius kinetics, time-series regression forecasting,
   FEFO inventory control, and multi-tier role-isolated web architecture.

Q2: What is Mean Kinetic Temperature (MKT) and why not use simple arithmetic average?
A: Simple average assumes that 1 hour at 15°C and 1 hour at 5°C equals an average of 10°C.
   In biology and chemistry, reaction rates double or triple for every 10°C increase
   (Arrhenius law). High temperatures cause exponentially more protein denaturation than
   low temperatures. MKT takes this non-linear exponential thermal degradation into account.

Q3: Which machine learning algorithm is used for demand forecasting?
A: We implemented Ordinary Least Squares (OLS) Polynomial Linear Regression combined with
   empirical Day-of-Week (DoW) seasonality weighting. Historical trends (y = mx + c) are
   computed with `numpy.polyfit()`, modulated with weekday clinical multipliers (e.g. Tuesday
   pediatric peak of 1.25x vs. Sunday lull of 0.30x), and bounded by ±1.2 sigma confidence
   intervals.

Q4: What is the difference between FIFO and FEFO?
A: FIFO (First-In, First-Out) dispatches whatever arrived first. In pharmaceuticals,
   different batches have varying shelf lives. FEFO (First-Expired, First-Out) sorts batches
   strictly by expiry date so the lot closest to expiration is always consumed first,
   eliminating expiration wastage.

Q5: What happens when a cold-room temperature breach occurs in your system?
A: The thermal engine analyzes the reading. If temperatures exceed 8°C or fall below 2°C,
   health score penalties accumulate. If critical thresholds are crossed, the system
   automatically triggers an electronic tripwire, updating the batch status in the SQLite
   database from `ACTIVE` to `QUARANTINED_HEAT` or `QUARANTINED_FREEZE`, preventing dispensing.

Q6: How do the Hospital and Manufacturer portals interact?
A: They communicate via relational foreign-key REST workflows:
   1. Medicine Requisitions: Hospital requests appear in the Manufacturer's Fulfillment Desk.
   2. Demand Aggregation: Individual hospital forecasts are synthesized into national totals.
   3. Query Desk: Clinical inquiries submitted by hospital staff route to manufacturer
      representatives who post official responses.

Q7: What is the significance of the 500-record dataset?
A: The dataset tracks real-world vaccine batch001 at the Jharkhand storage depot through
   a 3-phase cold-chain lifecycle: 720 hours in ultra-low storage (-70°C), 119 hours in thawed
   refrigeration (2°C-4°C), and a thermal excursion spike to 14°C triggering an auto-discard.

Q8: How did you ensure strict portal isolation?
A: Dedicated login routes (`/hospital-login` and `/manufacturer-login`) validate user roles.
   If a user with role `HOSPITAL` attempts to enter the manufacturer dashboard, the client
   and server enforce immediate redirection and session repudiation.
